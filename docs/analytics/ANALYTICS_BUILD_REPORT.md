## A1 Click-counting correctness and privacy review (commit `50edc21`)
**Done:** one legitimate outbound click is counted once.
- Root cause (confirmed in code): with JavaScript, `interactions.js` posted to `track-click.php` (wrote `tool_clicks`) and then followed `redirect.php?...&tracked=1`, which ignored the flag and wrote again; the browser also sent an `outbound_click` event next to the server's.
- Fix: `outbound_click.php` is the **only** recorder, called once by `redirect.php`; `track-click.php` is read-only (stays so cached pages keep working); `interactions.js` no longer intercepts links; `app.js` no longer sends the event; built assets rebuilt. Not counted: bots (tool_clicks used to include them), prefetch and prerender, HEAD requests, a repeat within 5 seconds (double click), over 20 per 10 minutes (existing guard). The legacy `tracked=1` flag changes nothing. The rollup now counts only server-written outbound events (`prop2` sponsored/organic), so any older browser events cannot double count.
- Unchanged: destination from the catalogue only, safe-URL check, `Referrer-Policy: no-referrer`, affiliate and sponsored attribution, the visitor is always redirected even if counting fails.
- Privacy: `PRIVACY_AND_RETENTION.md` (inventory, findings, options, proposed retention; 13 months only a ceiling); `analytics_retention.php` and `scripts/analytics_purge.php` (dry run by default, no default period, nothing scheduled); device class (D3) via an optional additive column, one word, no user agent stored.
- Files: `outbound_click.php`, `redirect.php`, `track-click.php`, `assets/js/interactions.js`, `app.js` (+ built files), `adm_analytics.php`, `analytics.php`, `analytics_retention.php`, `scripts/analytics_purge.php`, `database/analytics_a4_device.sql` and rollback, tests. Tests: `analytics_a1_test.php` **45 passed** (one-record-per-click with injected recorders, every exclusion, legacy flag, static single-writer checks, retention on in-memory SQLite, device classes, DNT, insert without the column).
- Limits: the real `redirect.php` and browser flow are verified on staging only; the visible click counter on cards now refreshes on the next page load.
